## Closed contract

Listbox uses default single or explicit multiple mode, opaque canonical strings,
empty ''/[], bounded empty-capable catalogs and readonly values. It reuses B's
schema/selection/index.ts exactly. No alternate multiple flag, group, max, nullable
sentinel, arbitrary render callback, HTML, CSS or native event is public.

The official narrow React Aria ListBox owns vertical roving focus, navigation,
typeahead, pointer selection and scoped Escape behavior. Locale is explicit and
finite, default en-US. App controls text direction. Selected keys remain host
controlled; callback false vetoes and true/void allow a logical request. Runtime
invalid/async/throwing decisions fail closed. Binder writes return Result.success.

Existing disabled keys remain visible/serialized and can be cleared. New disabled
selection, including reset restoring a now-unselected disabled initial key, is
refused. Requiredness validates native forms without prohibiting empty editing
state. Readonly required emptiness remains invalid. Whole-widget disabled omits
entries and Tab stops. Native reset never cancels unrelated controls.

## SDK failures recorded before narrow repairs

- Native isComposing Enter/keyCode13 selected an option. A local capture boundary
  suppresses composing commits/typeahead without replacing SDK navigation.
- Accepted Clear disabled its focused button and lost meaningful focus. The
  logical action returns focus to the list while preserving host-placed focus.
- RAC filters readonly/required/invalid/disabled/busy root attributes and keeps
  an all-disabled root tabbable. A closed trusted semantic bridge sets these
  attributes in layout effects. A scoped MutationObserver watches only tabindex
  while disabled, avoids self-trigger loops and disconnects on cleanup.

ARIA 1.2 permits these listbox states and vertical is its implicit orientation:
https://www.w3.org/TR/wai-aria-1.2/#listbox . The bridge does not replace collection
or active-item internals. Hydration tests verify IDs/stores and recoverable-error
absence; static SSR retains the SDK's baseline attribute projection until layout
effects run. No claim is made that the bare SDK forwards unsupported attributes.
